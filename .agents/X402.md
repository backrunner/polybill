# x402-paysdk 集成设计

## 1. 已确认的本地接口

本机 `../x402-qrpay` 的 remote 是 `https://github.com/backrunner/x402-paysdk.git`，发布包为
`x402-paysdk@0.1.0`。公共入口只有：

```ts
import { pay } from "x402-paysdk/pay";
import { createPaymentRef } from "x402-paysdk/receive";
import { MerchantClient } from "x402-paysdk/merchant";
```

Polybill server adapter 只依赖 `x402-paysdk/merchant`。不 deep-import 私有 workspace 包。已确认
merchant API 提供：

- `MerchantClient`
- merchant registration/key rotation
- `createPaymentRef`、get/list/revoke ref
- order/refund helpers
- `verifyReceipt`、`verifySignedPaymentReceipt`
- transaction status/history 和 `reconcile`
- signed notify verification、nonce store interface

gateway 同时有 native 和 Cloudflare Worker 实现，Worker 使用 D1/KV 相关 store。Polybill 不复制
这些 Rust/TS 协议逻辑。

## 2. Role in Polybill

x402 adapter 是 `payment.one_time = native`、`payment.asset_settlement = native`、
`refund = conditional`、`subscription.create = unsupported`、`subscription.mandate = unsupported`
的 provider。Catalog、customer、license、voucher 和 subscription schedule 仍由 Polybill 管理；
当前 adapter 不会把未实现的 scheduler 暴露成可调用的 subscription command。

x402 connection 的 commercial model 是 `settlement_network`：merchant/宿主仍是 seller of record，
负责 tax calculation/collection、税务发票、退款政策和争议处理。链上 receipt 是结算证据，不是
MoR 税票。要求 provider MoR 的 `commercialPolicy` 必须在创建 PaymentRef 前拒绝 x402 routing。

```text
SKU/Price -> Polybill Order -> PaymentRef -> payer x402 flow
                                      |
                                      v
                              signed receipt + tx hash
                                      |
                         verify signature + chain finality
                                      |
                              canonical Payment
```

## 3. Configuration

```ts
interface X402ConnectionConfig {
  provider: "x402";
  environment: "test" | "live";
  gateway: string;
  apiKey: SecretResolver;
  notifyHmacKeys?: SecretKeyRingResolver;
  payTo: string;
  network: string;
  asset: "USDC";
  settlement:
    | {
        kind: "fixed";
        pricingCurrency: "USD";
        atomicPerMinor: "10000";
        acceptPegRisk: true;
      }
    | { kind: "quote"; resolver: SettlementQuoteResolver };
  trustedReceiptSigners: readonly string[];
  minConfirmations: number;
}
```

`environment` 是 Polybill routing isolation；实际安全边界还包括 network/chain ID、asset contract、
gateway origin、facilitator 和 RPC。test connection 只能使用允许的 test network/gateway，不能只靠
字符串 `test` 放松 receipt validation。

gateway origin 必须 HTTPS（localhost 开发例外）且无 credentials/path traversal。`payTo`、network、
asset、amount、invoice ID 和 expiry 同时绑定 PaymentRef/Order。

当前 `x402-paysdk` 只接受 USDC，amount 是 6 位 decimals 的原子整数字符串。canonical Price/Order
仍以 ISO-4217 `Money` 计价，adapter 不能直接复用其 minor-unit 数字。`SettlementQuoteResolver`
返回绑定 Order 总额、network、USDC contract、decimals、atomic amount 和 expiry 的 quote。
`fixed` 策略只允许商户明确接受 USD/USDC 脱锚风险时使用；`10000` 表示 1 美分对应 10,000 个
USDC atomic units，而不是 SDK 默认汇率。

## 4. Checkout mapping

`billing.checkouts.create()` 对 x402 返回：

```ts
interface X402CheckoutAction {
  kind: "x402";
  checkoutId: CheckoutId;
  orderId: OrderId;
  refId: string;
  url: string;       // x402pay:// or hosted relay URL
  expiresAt?: IsoDateTime;
}
```

流程：

1. 创建/claim Polybill Order 与 idempotency key。
2. 通过 settlement policy 解析并持久化 quote；验证 pricing amount、USDC asset identity、6 decimals
   和 quote expiry，禁止隐式汇率或舍入。
3. 用 canonical Order ID 作为安全的 `invoiceId`/mapping，创建 fixed-amount PaymentRef。
4. 保存 `refId`/ref URL mapping、原 Order Money、quote 和完整 expected settlement tuple。
5. 返回 x402 URL；Polybill 不持有 payer wallet/private key。

PaymentRef expiry 不能晚于 quote expiry。动态金额 PaymentRef 不用于已知订单结算；订单必须 fixed
amount，防止少付/错付。quote 过期时创建新的 Payment attempt/quote，不改写旧 attempt。

生产 `notifyUrl` 使用统一路径 `/webhooks/polybill/x402/:connection`，且必须满足
`x402-paysdk` 对公网 HTTPS host 的校验。离线测试直接构造 Web `Request`，不为了测试绕过生产 URL
校验或启动公网 tunnel。

## 5. Settlement verification

notify 不是 finality。收到 `payment.settled` 后：

1. 使用 `verifySettlementNotify` 在 raw body 上验证 HMAC、key ID、timestamp 和 nonce。
2. 校验 header/body 的 merchant/ref/event 一致。
3. 通过 `verifySignedPaymentReceipt` 验证 signer、kid、content hash 和 expected fields。
4. 通过 gateway `verifyReceipt` 或 `getTxStatus` 检查 chain，要求 `minConfirmations`。
5. 比较 payTo、payer（若已知）、amount、asset、network、chain ID、resource/ref/payment ID。
6. 写 Payment evidence；只有 signature valid 且 chain confirmed 才标记 succeeded。

如果 notify 缺失，reconciler 使用 tx history、stored receipt/ref 和 gateway API 恢复。若 settlement
成功但 receipt 丢失，调用 `recover-settlement` 路径，而不是要求用户重复支付。

## 6. Idempotency and replay

- canonical Payment attempt 绑定 PaymentRef、expected amount 和 payment identifier。
- notify nonce 存入共享原子 `NotifyNonceStore`；memory store 只用于测试。
- D1/DO key 包含 connection + key ID + nonce，TTL 至少覆盖 tolerance。
- 相同 tx hash 不能支付两个不同 canonical orders；唯一约束阻断 replay。
- 相同 Order 的重复 valid notify/API poll 只推进一次 projection/outbox。

## 7. Refunds

如果 gateway/order mode 与商户 signer 配置满足 x402-paysdk refund contract，映射为
`refund = native/conditional`：

- merchant-controlled wallet/HSM signer 完成 reverse payment。
- 校验 original receipt hash、original payment ref、refund amount、payer/payTo、sequence。
- 累计退款不能超过 original amount。
- 部分退款使用原 settlement quote 对应的资产比例和明确 rounding policy；不按退款时新汇率静默换算。
- signed refund receipt 和 chain finality 都进入 evidence。

没有 signer、order mode 或目标网络能力时返回 unsupported；不能在 Polybill DB 中把状态改为
refunded 来代替链上退款。

## 8. Subscription semantics

x402 v1 没有可复用的自动扣款 mandate。Polybill 可以提供 `scheduled_invoice` workflow：每个周期
生成新的 Order/PaymentRef，并通知 customer 主动签名。只有本期 settlement 成功后才延长
entitlement。

这不是自动续费，API 必须返回：

```ts
{ support: "emulated", fidelity: "workflow", strategy: "customer_reauthorization_each_cycle" }
```

需要真正自动续费的 subscription 继续由 card/MoR connection 负责；同一 plan 可允许 customer
选择 x402 手动周期支付，但 UI/条款必须说明。

## 9. Testing

- 复用 x402-paysdk 自身 canonical receipt/signature helpers 和 fixture，不手写简化协议。
- fake gateway/facilitator 测试 verify、settle、timeout、settled-but-response-lost 和 recovery。
- 使用 deterministic signer/test keys 验证 trusted/untrusted signer、内容篡改、错 amount/payTo。
- fake chain/RPC fixture 测 0/不足/足够 confirmations、reorg/failure、duplicate tx hash。
- Miniflare + D1 测 shared nonce store 和 inbox/outbox；测试无需公网 notify。
- 可选 test network job 只用于兼容性 smoke，不作为 CI 正确性的唯一证据。

## 10. Dependency/version policy

- `@polybill/provider-x402` 对 `x402-paysdk` 使用受控 semver/peer range，并在 CI 测最低与最新
  兼容版本。
- 已调研的 `0.1.0` merchant runtime 使用 Web Crypto/`fetch` 且没有 `node:*` runtime import，
  但 `MerchantClient` 直接调用全局 `fetch`，没有 transport/AbortSignal 注入口。stable adapter 前应
  优先给上游 public client 增加 fetch/signal 注入并发布；临时方案只能通过其 public、可覆写的
  `request()` 建立短生命周期 client，并以 compatibility test 证明 timeout、redaction 和 evidence，
  不能 patch `globalThis.fetch`。
- `x402-paysdk@0.1.0` package metadata 声明 Node engine；即使当前 runtime source 是 Web API，仍须
  对实际发布 tarball 执行 workerd import/bundle smoke，不能仅凭源码推断 Cloudflare 兼容。
- package public export 或 receipt schema 变化触发 adapter fixture replay。
- Polybill 不复制常量、chain address 或 network validation；从 x402 public API/validated config
  获取，避免两套协议漂移。
